## Decided beyond the dispatch's letter (accept or reject)
1. **The late store holds every write, the first too.** Section 5 let the first write go straight through.
   - That write's transform runs on the main thread (:351). The first read releases the next write and waits for it on that thread, so the test would hang whenever the first write had not yet run.
   - Avoiding the hang would mean skipping the release, which puts the timing back.
   - Holding every write gives exactly one release per read, so the result never depends on timing. The interleaving it forces is the one section 5 describes.
2. **"Today's wait" in the late-store case reads through the store the ViewModel holds,** because the late store releases writes only on reads made through it. For the existing case that store was the real repository, so in step 1 it behaved exactly as before.
3. **Between steps 1 and 2, the late store now hands a released write's result back on IO,** as DataStore's own actor does (:200-202, :244-245). Step 1's failure does not depend on this [inferred]. The revert check ran today's wait over the final version and failed the same way [observed].
4. **The existing case's body moved into a shared function.** Its name and every assertion's text are unchanged.
5. **The revert branch is kept.** `crowded-icons-test-fix-r1` (c1a98670a) stays on origin, since the dispatch did not ask for it to go. Delete it if you want.
