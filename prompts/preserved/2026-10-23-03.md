**The server contract** (PR #381; accepted by the planner; the routes aren't deployed yet):
- `GET /routing/area.json?south=&west=&north=&east=` returns `{"run_id","osm_timestamp","files":[{"name","size","sha256","url"}]}`.
- Then `GET` each `url`, which returns the bytes with a sha256 header.
- Errors are a status plus `{"error","message"}`: manifest_missing 503, run_missing_square 503, checksum 502, outside_coverage 404, too_large 413, bad_request 400, forbidden 403, rate_limited 429 with Retry-After.
- `MAX_ROUTE_AREA_SIDE_KM = 50`.
- **The app key:** every request carries a header. The planner sets this contract (#381's coder is told the same):
  - the header is named `X-Forager-App-Key`;
  - the app reads the key from `BuildConfig.ROUTING_APP_KEY`, filled from the Gradle property `forager.routingAppKey` or the environment variable `FORAGER_ROUTING_APP_KEY`, and empty when neither is set;
  - CI and tests use a fake server, never the real key;
  - the key is never committed.

**Build:**
