Mark each figure as measured, read or inferred. Measure the SD card's real sequential write and
read speed with a 2–4 GB `dd` of a temporary file **on the card**, then delete it. That test file
is the only write allowed.

- **A. Free the old output before the build reaches Planetiler.** Ways to do it: move the old

  then fails, and there is no output at all for a day?
- **B. Downloads on the SD card.** Download straight to `/mnt/archive`, behind symlinks as today.
  The cost is an MD5 read from the card.
- **C. The merged extract on the SD card.** Planetiler reads it through about 1.5 passes. What does
  the card's measured read speed do to osm_pass1 and osm_pass2?
- **D. A correct floor.** Replace the fixed 110 with a check that fails in minutes when a full run
  can't fit. How should the need be estimated, and from what?
- **E. Combinations.** Which smallest set makes Sunday fit with margin? Show the arithmetic.
- **F. Download restarts in `curl_resume`.** Not a disk matter, but the same weekly path. Price
  adding the speed-limit and restart used in `fetch-then-build-261017.sh`.
- **G. DNS.** The last two weekly firings failed to resolve `download.geofabrik.de`. Is that
  still so on Wi-Fi? Check with one `getent hosts download.geofabrik.de` and the resolver config.
  Read-only.
