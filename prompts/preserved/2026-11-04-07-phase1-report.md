## 3. Mechanism prediction

This assumes S1 is settled as A3 is written. If the owner picks different night colours, only the two values in `nightSelectedChipColors` change.

**Changes in MapModeChips.kt.** The file goes from about 116 to about 150 lines.

- **`colors`:** the existing `if (standsAside)` stays. Its else branch, `FilterChipDefaults.filterChipColors()` at :105, becomes `normalChipColors()`. That is a new `@Composable` function returning:
  - `nightSelectedChipColors()` when `LocalForagerDarkTheme.current`. This is a new function: `filterChipColors(selectedContainerColor = MushroomDeep, selectedLabelColor = PureWhite)`.
  - `FilterChipDefaults.filterChipColors()` otherwise.
- **`border`:** the `FilterChip` call gains `border = mapModeChipBorder(selected = mode == mapMode, standsAside = standsAside)`. That is a new function returning:
  - Material's own `filterChipBorder(enabled = true, selected)` when `standsAside`;
  - otherwise `filterChipBorder(enabled = true, selected, selectedBorderColor = MaterialTheme.colorScheme.onSurface, selectedBorderWidth = 1.dp)`.
- **Why this matches the design:**
  - The outline colour comes from `onSurface`, Bark by day and Cream at night, so the border needs no theme branch.
  - The theme and grey conditions live in the new functions, not the row (C1).
  - The unselected chips are unchanged by construction. Only `selected*` colour fields and the selected border parameters are overridden, so the unselected fill (transparent), label (`onSurfaceVariant`) and outline (1 dp `outlineVariant`) stay Material's.
  - The grey chip is unchanged by construction: its colours branch isn't touched, and its border is Material's default.
  - The row's `MapModeChipSelectedFill` semantics will now record #A2612C at night, on unselected chips too, exactly as it records `secondaryContainer` today.

**Why the tests fail before and pass after:**

- **Outline, day and night:** at pre-main the selected border is 0 dp transparent, a 1 px invisible hairline. On the chip's middle row the fill starts at the node's left edge, with no `onSurface` pixel there. After the change, `ceil(1 dp × 3.0)` = 3 px of `onSurface` sits at x 0-2 at xxhdpi, and the fill starts at x 3.
- **Night fill:** pre-main draws #6B421A (`secondaryContainer`); #A2612C is expected.
- **Night label:** pre-main draws #F6DFC8, so the chip has no #FFFFFF pixel at all. After the change the glyph cores are #FFFFFF.
- **Unchanged cases** (day fill and label, unselected chips in both themes, grey chips with no outline in both themes): these pass before and after, by construction. Only reverts can show they bite (section 4).
