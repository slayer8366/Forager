## What to build

### 1. Fix the stall

After attempt 2 (direct open of a physical ID) was refused with CameraAccessException, the probe never ran attempt 3 and never handed back. The app held camera 0 until the planner force-stopped it.

- Reproduce it in a fake-camera test first: it must fail on today's code.
- Fix it so a refused or failed open on any attempt still runs the remaining attempts and always hands back.
- Then add a per-attempt timeout, so no attempt can hang the probe.

### 2. Reach, per physical camera

For every camera the phone describes, enumerate:
- every ID in `getCameraIdList`;
- every physical ID of every logical camera;
- each one's facing, focal length, sensor size, colour pattern, RAW sizes and capabilities.

Then for each back camera, attempt in turn:

- **(a) Through the logical camera.** A RAW physical stream for that physical ID, on each logical camera that lists it. Log the session query, whether it configured, 1 single frame, and an 8-frame burst with its rate. Log the active physical ID and the per-physical result IDs on each frame.
- **(b) Direct open.** Opened directly, if the ID is in `getCameraIdList`. Then the same frames and burst.
- **(c) The pair case.** Two physical RAW streams at once, for example main and ultra-wide, if the platform's multi-camera rules allow it. Log the outcome only.

Log each attempt's verdict:
- `reachable_raw` (with its rate and size);
- `reachable_no_raw`;
- `refused` (with the error);
- `unsupported` (the session query said no).

Never guess (CLAUDE.md).
