## What was built
- **Trip bubble:** name, date, MGRS, then "Elevation N ft" where the ground height is known. Below that, Navigate · Plot route · Details. No latitude/longitude, no Directions.
- **Trip card:** name, "Trip date" (no row for an undated trip), MGRS, Coordinates, then Navigate and Directions centred. No Created or Used in. It opens only from the Maps tab bubble.
- **Waypoint card:** Navigate, then Directions on its right, centred, on the Maps tab, in Records and on a journal entry's map. Directions appears only where Navigate does and leaves the card open. The track card is unchanged.
- **Navigate to a trip as itself:**
  - The kind key is written only for a trip, and a missing key reads as a waypoint. So a navigation kept before the update resumes as before, and a waypoint's is stored exactly as it was.
  - A trip resolves against the trips, never the waypoints. A kept trip navigation waits for the trips to load instead of ending as deleted.
  - Back reopens the trip's bubble or card.
  - On arrival the trip's flag is hidden under the ring.
- **Plot route from a trip:** starts plotting from the trip's spot, under its name. While plotting, tapping a trip with no route adds it as the next stop; a trip with a route still opens its route.

## Decided beyond scope (yours to accept or reject)
1. **The trip as a waypoint-shaped value in memory**, so the HUD, line, arrival and way-to take it unchanged. Its creation time is set to 0, and nothing reads it. The alternative was a new target type threaded through the HUD and the 1,440-line scaffold.
2. **The kind key is written for a trip only**, so a waypoint's navigation keeps exactly its two existing keys.
3. **The line and way-to read the trip from the stored trips**, not the screen's loaded list, so a navigation picked back up at start never misses its trip by read order.
4. **The trip's Navigate appears only where `onNavigateToTrip` is passed**, which is the Maps tab, wired in MainActivity.
5. **`RecordDetailsSheet` takes two more defaulted parameters** instead of a bundle.
6. **The field name `waypointId` is kept**, holding a trip's id when the kind is trip, with KDoc saying so.
