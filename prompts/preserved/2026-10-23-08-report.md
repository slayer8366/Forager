signatures and annotations, and drops constructors, that no rule keeps, so each library's own rules decide the
answer. Several rows rest on the `-keepclassmembers enum *` rule at AGP default `:45-48`.

## 2. Shrinking only vs full obfuscation

- **`isMinifyEnabled = true` alone obfuscates.** R8 renames unless `-dontobfuscate` is present, and no rule file in
  play has it (item 1, "Global flags"). The optimize default stays: AGP 9.3.1 no longer accepts
  `proguard-android.txt`. `ProguardFiles.class` carries the message "`getDefaultProguardFile('proguard-android.txt')`
  is no longer supported since it includes `-dontoptimize`". So the one-line change both shrinks and obfuscates, which
  is what Play's "Obfuscation" and "DEX code optimization" lines measure. **Whether Play's threshold is then met is
  visible only after an upload** (could not determine).
- **`isShrinkResources = true`** removes resources that no kept code references. It needs minify. It adds a smaller
  APK, and nothing to Play's obfuscation figure. Its risk is a resource reached only by name at runtime: nothing in
  `app/src/main` does that (no `getIdentifier`), and `res/` holds only `drawable`, `font`, `mipmap-anydpi`, `values`
  and `xml`. The risk is low, but it is a second variable for the same phone check. **Recommendation:** leave it out
  of this dispatch, as one change measured at a time, and add it in a later small one if the owner wants the size.
  This is a decision for the owner and is not made here.

## 3. The mapping file

- **How it reaches Play: inside the .aab, with no upload step needed.** In AGP 9.3.1's bundle task,
  `PackageBundleTask$BundleToolWorkAction` reads `getObfuscationMappingFile()` and adds it under the metadata
  namespace `com.android.tools.build.obfuscation` as `proguard.map` (bytecode offsets 1755-1785), so the mapping
  travels in `BUNDLE-METADATA` of the bundle that `release.yml:222` uploads. `release.yml` needs no change, and its
  track and draft status are untouched. That Play Console then deobfuscates Android vitals crashes and ANRs from that
  metadata is Google's documented behaviour; it is not checkable from this repository (inferred).
- **Stack traces from testers.** A crash in Play vitals should appear already deobfuscated (inferred, as above). A
  logcat trace a tester sends by hand is obfuscated, and has to be run through R8's `retrace` with **that exact
  build's** mapping. Where that mapping lives is a real gap:
  - `release.yml:16-17` deliberately uploads no build artifacts, so the mapping exists only inside the uploaded
    bundle (in Play) and on the discarded runner.
  - Options for the owner: (a) download it from Play Console per release (inferred to be offered there); (b) have
    `release.yml` keep `app/build/outputs/mapping/release/mapping.txt` somewhere private. The repo is public, and the
    code it maps is already public, but changing `release.yml`'s no-artifact rule is the owner's call; (c) regenerate
    it by rebuilding the same commit, which assumes R8 output is deterministic for identical inputs (not verified).
  - Not decided here.
- **Line numbers in retraced traces.** The AGP default keeps `Signature`, `InnerClasses` and the annotations
  (`:13-19`), but not `LineNumberTable` or `SourceFile`. Whether this AGP's R8 keeps line numbers by default could not
  be determined without a build. The build stage should check a retraced trace for line numbers. If they are missing,
  `-keepattributes SourceFile,LineNumberTable` is the named fix (2 lines).

## 5. How to prove it works

**CI (can fail, and needs no key):** the existing `release-compile` job (`ci.yml:547-613`) already runs `packageRelease`
and `packageReleaseBundle`. With minify on, `minifyReleaseWithR8` becomes a dependency of both, so R8 runs on CI
with no new job and no key. Proposed checks, each with a positive control:

1. **R8 ran.** Add `minifyReleaseWithR8` to the required-task loop at `ci.yml:582`.
   - Control: on current pre-main, with minify off, the task is absent and the check fails.
2. **It obfuscated.** A small check on `app/build/outputs/mapping/release/mapping.txt`: the file exists, and at least
   N `com.zynergylabs.forager.` classes map to a different name.
   - Controls: no mapping file (today) fails; a scratch-branch `-dontobfuscate` fails.
   - Per CLAUDE.md, any revert check reads the build log for compile errors before citing results, and restores from
     a saved copy, not git.
3. **The names that must survive did survive**, as kept self-mappings:
   - `ForagerDatabase` and `ForagerDatabase_Impl`, `FungiIndexDatabase` and `FungiIndexDatabase_Impl`;
   - `ScheduledBackupWorker`;
   - and, for each `@Serializable` class, `Companion` plus `serializer()` present.
   - Control: the checker run on a doctored copy of the mapping with one of those names renamed must fail, naming that
     class.
4. **R8 warnings.** R8 errors on missing classes and writes `missing_rules.txt`. Any `-dontwarn` added to reach green
   is named in the completion report with the class and the reason. None is expected from item 1, but it could not be
   determined without a build.

**Robolectric or instrumented on the minified build: not possible here.**
- Robolectric runs unit tests against unminified JVM classes, not R8's DEX output.
- An instrumented run against the minified variant needs a device or emulator. CI has no emulator job (jobs `build`,
  `lint`, `release-compile`, `route-cutter`, `pmtiles-worker`; `ci.yml:60,496,547,619,663`), and a signed,
  installable minified APK needs either the release key or a new debug-signed build type, which would touch the
  signing config. Out of bounds for this dispatch.
- So runtime proof is phone only.
