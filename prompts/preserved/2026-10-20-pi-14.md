## What is known (re-check each, with file and line or URL and time)

1. **Geofabrik publishes the islands as nested regions:** `north-america/us/puerto-rico`, about
   70 MB, and `north-america/us/us-virgin-islands`, about 3 MB. Each has `-latest`, dated daily
   files with `.md5`, `-updates/state.txt` and a `.poly`. pi-03 read this, and the planner
   spot-checked it at 2026-10-20 03:44Z.
2. **They share one snapshot with `us` and `canada`.** All four `state.txt` files read
   `timestamp=2026-10-18T20:25:06Z`, spot-checked. The script's same-snapshot rule
   (`build-usca.sh:478-483`) can stand.
3. **The script assumes a region name is a bare file stem directly under `USCA_GEOFABRIK_BASE`:**
   - in the size, `.md5` and download URLs, `$USCA_GEOFABRIK_BASE/${file[$s]}`, at `:509`, `:526`
     and `:529`;
   - in local file names, `$s-$local_date.osm.pbf` at `:456`;
   - in the cleanup globs, `"$SRC/osm/$s-"[0-9]*` at `:325-326`;
   - in the outline file name, `$s.poly`, in the sources stage.

   A name like `us/puerto-rico` gets `state.txt` and `-latest` right but builds a flat download URL
   that returns 404 (spot-checked), and it would put files in subdirectories.
4. **`basemap_matches` compares the timestamp and only the first region's sequence**
   (`build-usca.sh:498`). Planetiler's metadata holds the merged header, which carries only the
   first region's. So a US + Canada basemap from the same snapshot would pass for a four-region run,
   and reuse a basemap with no islands. As things stand, only a coverage point in the islands would
   catch it.
5. **The islands sit in two routing squares, `W70_N15` and `W65_N15`,** both in the last band,
   −75:180 (pi-03). At pi-03's estimate of about 3.4M nodes, the band stays well under
   `USCA_BROUTER_MAX_BAND_NODES`.

## What to build

- **Separate a region's path from its file stem.** Path is for URLs; stem is for file names, globs
  and outlines. For example, `USCA_REGIONS="us canada us/puerto-rico us/us-virgin-islands"` with
  stem = basename, or a pinned map. Propose the shape in Phase 1.
  - `us` and `canada` must behave exactly as now. Today's files, links, the published manifest's
    sequence string and the skip check all have to keep working. The manifest's sequence format
    carries region names, so state in Phase 1 whether the names in it change.
  - Every download, `.md5`, size, `state.txt`, `-latest` and `.poly` URL is built from the path.
  - Every local name and cleanup glob is built from the stem.
- **The outlines.** Four outlines are merged by `merge_poly.py`. Add a test that joins four,
  including the Puerto Rico and USVI shapes' slight overlap. pi-03 found that `merge_poly.py` loops
  over any number of outlines, but the tests only ever pass one or two.
- **The coverage points.**
  - San Juan comes back: `san-juan:-66.1057:18.4655`, in square `W70_N15`.
  - Add one for the USVI. pi-03 proposed Charlotte Amalie, `-64.9307:18.3419`, in square
    `W65_N15`, from general knowledge. Confirm the point lies in that island's outline, using the
    `.poly` read from Geofabrik's page (HTML and `.poly` are fine; no `.osm.pbf`).
  - Check the USVI square passes `> 100000` bytes. pi-03 estimated only about 3× margin, from a
    ratio taken from Hawaii. If the estimate is shaky, say so and propose the threshold.
- **The basemap hazard (4).** The coverage points above already refuse an island-less basemap at
  validation, after routing. Also make `--basemap` refuse earlier when the run's regions are not the
  basemap's. Planetiler's metadata alone cannot show this, so propose a mechanism in Phase 1, for
  example a small sidecar the build writes next to the archive that lists its regions and
  sequences.
  - **Stop and ask** if the only mechanism would change how today's kept basemap is accepted.
- **The wording.** Correct the islands' wording in `build-usca.sh`'s header, `pins.env` and the
  README, so they say the islands are regions of their own.
- **The disk check.** Confirm it adds the islands' bytes to its input total without change. It
  should, because it sums the regions' sizes.
