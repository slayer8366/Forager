## 2. How a trip's location reaches the elevation line, Plot route and Navigate

### Elevation (A1): no data change

- **The height is read from a position, not a waypoint.**
  - `rememberWaypointElevationLine(lat, lng, unit)` reads `LocalGroundHeightSource.current.groundHeightAt(LatLng)`, keyed on the spot (`MapBubbleLayer.kt:247-253`).
  - `waypointElevationLine` formats it (`MapBubbles.kt:386-389`).
  - The source works on a `LatLng` (`GroundHeight.kt:14-16`) [read].
- **What changes for a trip:** today it's applied only to `WaypointContent` (`MapBubbleLayer.kt:117-123`). For a trip it means giving `MapBubbleContent.Trip` an `elevation` field and applying the same read to `trip.location` [inferred].
- **Units:** the line follows the Units setting. It reads "Elevation N m" in metric, not always "ft" (`MapBubbles.kt:387`) [read].

### Plot route (A3): no data-model change

- **How the trip gets in:** a trip's "Plot route" would call `plotting.actions.onStartPlotting(RouteStop(trip.name, trip.location))`, resolved from `sources.plannedTrips`, as the waypoint closure does from `sources.waypoints` (`MapBubbleLayer.kt:167-177`) [inferred from read]. Nothing changes in `RoutePlottingViewModel` or in storage.
- **What a trip as a stop means for a saved route:**
  - The route keeps its own copy of the stop, name and position, with no id (`PlottedRoute.kt:36-37`) [read].
  - It is stored in `planned_trip_route_stops` (tripId, stopIndex, name, lat, lng; schema 23) [read].
  - Deleting the original trip later leaves the route as it was [inferred].
  - The save dialog offers "<trip name> to <last stop>" (`RoutePlotDraft.kt:42-46`) [read].
  - The saved route is a new trip whose pin is its first stop (`SavePlottedRouteUseCase.kt:24`; `PlannedTrip.kt:23-24, :34`) [read]. That puts it exactly on the original trip's pin.
  - Every trip draws the same flag (`OverlayFeatures.kt:156-166`) [read], so the spot becomes two identical flags, a crowded stack [inferred]. A route from a waypoint already puts a flag on the waypoint's pin, but there the two glyphs differ.
- **Unruled: tapping a trip while a route is being plotted.**
  - A trip without a route still opens its bubble then (`CompactMapRoutePlotting.kt:88-92`) [read].
  - Its new "Plot route" would start a new route and drop the one being plotted, without asking (`RoutePlottingViewModel.kt:103-106` replaces the whole state) [read].
  - Today this can't happen with a waypoint: tapping one while plotting adds it as a stop (:78-87) [read].
  - Stop S5.
- **Trips that carry a route never show a bubble:** tapping one opens the route at once (`CompactMapRoutePlotting.kt:88-92`, "Opens the route straight away") [read]. So the new bubble and card only ever apply to trips without a route.
