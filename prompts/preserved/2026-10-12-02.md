## Phase A: the check (read-only; no build, no Gradle anywhere)

1. **List every native library the app ships.**
   - Download the newest debug APK artifact from main's CI (`gh run list --branch main`, then `gh run download`). List `lib/*/*.so` and the ABIs.
   - The APK's libraries may already be stripped by the build, so they tell you *which* libraries ship, not whether their sources carry symbols.
2. **Check whether the sources carry symbols.**
   - For each library, find the dependency it comes from. Download that dependency's published archive (AAR) directly from its Maven repository with `curl`, at the exact version the project resolves. Read the versions from the version catalog and its comments. If a version is resolved transitively and can't be pinned without Gradle, say so.
   - Inspect each `.so` with `readelf -S` / `file`, and report whether it has a `.symtab` and any `.debug_*` sections, or only `.dynsym`.
3. **Find out what the owner's build machine would need.**
   - Check whether an Android NDK is installed in the SDK this laptop uses (`ls ~/Android/Sdk/ndk` or wherever `local.properties` / `ANDROID_HOME` points, read-only).
   - From the plugin's documentation, check whether extracting symbols needs the NDK, and which version.
4. **Report and stop.** Return a Phase A report as your final message (see "Final message"), and commit it as `docs/audits/2026-10-12-native-symbols-check.md` on a new branch `native-symbols`, cut from origin/main, pushed. Stop there if:
   - **(a)** no shipped library carries any symbols beyond `.dynsym`. The planner takes that back to the owner.
   - **(b)** the NDK is needed and not installed, or installing it is needed for the owner's release builds. Installing tools on the owner's machine is the owner's call.
   - **(c)** any premise above is false in a way that changes the plan.
   Otherwise, continue to Phase B.

## Phase B: the setting (only if Phase A doesn't stop)

1. On `native-symbols`, add the native debug symbol setting to the **release build type only**: `ndk { debugSymbolLevel = ... }`.
   - Choose `SYMBOL_TABLE` or `FULL`, and give your reason in a comment and the report. `SYMBOL_TABLE` is Play's documented minimum for readable native crash traces. If `FULL` would push the bundle or upload size past a Play limit, say so.
   - Add a short comment beside it saying why (owner, RECORD -917) and what was rejected (leaving the warning).
2. **Prove it on CI without a key.**
   - On a separate scratch branch `scratch-native-symbols`, cut from `native-symbols`, add a CI step that runs the standalone extraction task for the release variant (premise 4) and uploads its output as an artifact.
   - Then report the files produced (per ABI, per library, sizes).
   - If the extraction task can't run without the signing guard or a release bundle, **stop and report**. Don't work around the guard. The fallback is the owner's own release build, and you supply the one-line check for it: `unzip -l <bundle>.aab | grep -i debugsymbols` (or whatever the plugin actually writes; confirm the path).
3. **Prove nothing else changed.** Run the normal CI on `native-symbols` (`gh workflow run ci.yml --ref native-symbols`): `assembleDebug` and the full unit suite stay green. Report the suite counts against main's latest run.
4. **Write it up.** Update the report with Phase B's evidence and add one row to `docs/audits/README.md`. Push both branches. Don't open a pull request; the merge is the owner's word.
