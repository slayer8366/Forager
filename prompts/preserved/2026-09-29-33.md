## Build
1. **No duplicate regions on restore** (owner 3.1). Replace and Merge both skip an incoming offline region that matches one already on the phone: the same name, the same centre within 1 m, and the same radius. Its entry references are rewritten to the matching region.
   - Test a restore onto the phone that made the backup: the region count is unchanged, and the refs point at the live region.
   - Session 3 had 8 rows for 2 regions after a Replace and two Merges.
2. **The first scheduled backup waits** (owner 3.2). Turning the schedule on, or off and on, does not run a backup at once. The first run is at its scheduled interval. Test with WorkManager's test driver: nothing runs at enqueue, and one run happens after the interval.
3. **Keep the newest 5 scheduled backups** (owner 3.3). After a successful scheduled run, delete the oldest scheduled backups beyond 5.
   - **Only files the scheduled job itself created and recorded** (for example, their URIs kept in the backup DataStore) are ever deleted. Manual backups and any other file in the folder are never touched.
   - A failed delete is logged at WARN and never fails the backup.
   - **Stop** if the recorded list cannot be kept reliably.
4. **Ask for notification permission once** (owner 3.4). It is asked only the first time scheduled backups are turned on. If it is declined, it is not asked again for backups; the in-app next-launch notice covers it. The recording notification's own request is out of scope; leave it as it is.
5. **A deleted find still shown after Replace** (Session 3, a bug). After a Replace, the Journal still showed the report of a find the Replace had deleted. After a restore, every open entry or find whose record no longer exists is closed, as the post-restore reload clears the other screens.
6. **Replace and an orphaned region reference** (-155, -156). Replace keeps a cartography region-ref row whose region the backup lacks, so the row could meet a future MapLibre id. Replace drops such rows, as Merge already does. Count and log them.
7. **"Try again" after the schedule is off** (-153 flag). A notification's Try again runs one backup to the saved folder whether or not the schedule is still on. If the folder's permission is gone, it posts the existing failure and opens the Backup section when tapped.
