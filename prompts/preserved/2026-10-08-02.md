**Verify, write, then build on the planner's go. Usual Gradle rules: systemd-run 5G cap, no swap, Gradle -Xmx1536m and Kotlin 2g, Java temp at `$HOME/.cache/forager-test-tmp`, no daemon reused across scopes, `./gradlew --stop` at the end. No phone, no emulator.**

Written by the laptop planner on 2026-10-08 (UTC). Cut branch `search-keyboard` from `origin/main` (bfbba33f). App paths are relative to `app/src/main/java/com/zynergylabs/forager/app/ui/availability/`.

## Why

The owner, verbatim, with a phone screenshot (kept off GitHub) showing the keyboard covering the bottom of the search dropdown: "Real quick, the search menu doesn't bounce back up when the keyboard hits it. It used to do that. The search button is still hidden as a result. Fix this before the build". The cause is the search-order reorder (-697, PR #200). It removed the scroll-to-end on open and the keep-in-view after it (`coordinatesKeptInView` / `scrollToCoordinatesPending`), because the coordinates moved to the top, so nothing now keeps the bottom row (Set on map, Search) above the keyboard.

## The fix

Whenever the dropdown's viewport shrinks, for example when the keyboard opens, scroll the panel so its bottom row sits just above the keyboard, as before. A drag by the user stops the keep-in-view until the next open, matching the old behaviour (the old T3b rule). Opening with no keyboard still opens at the top, with the coordinates first (-697). Nothing else changes.
