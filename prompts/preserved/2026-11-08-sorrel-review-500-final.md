### Could the new pixel tests pass vacuously?
Two tests read rendered pixels (both new in #498; `OutlineEveryEdge` grown by #500's J4 cases). I read the reading code myself.
- **`NavigationCardEndLineInLineTest` (E21):** no. The side bar's line is found from pixels on six rows above its corner and must be one column set exactly `strokePx` wide (measured, so 0 or 2 px fails); the card's rows are those whose pixels from the edge out to 2 dp are exactly bare map (so the side bar's arc cannot be in the window), and at least one such row must exist; on every such row the line's columns must equal the side bar's, and each must be within 0.03/channel of the outline-over-map colour. If the card drew no end line at all, `lineColumns` returns `[]` and every row records a step ("columns [] (none)"), which is the message the coder's revert produced. The inside reference (2 dp inside the card) and the rail rows' outside reference are image reads, not constants. Tolerances: `EXACT` 0.008 (2/255 per channel, for "same flat fill"), `COLOUR_MATCH` 0.03; the old output (a 1 dp step) was 3 px off at xxhdpi, far outside either. The red run 42442571747 (16 of 16, "-3 px") is this test biting.
- **`NavigationCardOutlineEveryEdgeTest` (E19/E20/J4):** no. Every comparison is against a rendered pixel; `isLine` requires the pixel within 0.07 of the outline-over-fill luminance *and* more than 0.12 from the fill, so "nothing drawn" fails. Samples whose 3 dp-outside probe is not bare map are skipped (`continue`), guarded by `facing.isNotEmpty()` per capture and a reached-check for the E20 spot only; so an edge can be skipped entirely without a failure, which is a weakness of the design, not a vacuity (a skipped edge is one nothing faced the map on). #500's J4 addition, `overMapInside = roundedBottom && sy > 0 && run.any { overMap }`, excuses a corner miss only where a pixel inside 14 to 16 dp is on the *line's* side of the map by more than half the outline's gap, the same half-gap rule as the outer band; a bare-map pixel does not satisfy it (its luminance difference is 0). So it loosens where the line is counted, not whether a line must be there. Not vacuous.
