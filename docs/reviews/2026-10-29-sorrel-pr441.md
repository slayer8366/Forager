## Findings

- **N1 (`scripts/no-debug-sources-names.sha256`, `app/src/main` names).** Three of the 55 names are domain-shaped
  (`BackByRecord.kt`, `ReturnRecord.kt`, `SundownRecord.kt`), and four more are test names. A future pre-main change that reuses one of
  them for an unrelated file would be refused with a message that names no file (`verify-no-debug-sources.sh:50`), by design. The
  remedy is in that message: the PR's file list, or `--list` locally. Worth knowing when it happens; nothing to change.
- **N2 (`verify-no-debug-sources.sh:27`).** `-s` refuses an empty file, but a list of blank lines is non-empty: with two newlines and
  nothing else the script printed `Checked 3422 tracked files against 2 names` and passed. A list of non-hash garbage would pass the same
  way. A one-line tighten, if wanted later: count lines matching `^[0-9a-f]{64}$` and refuse unless it equals `wc -l`. Low risk: the list
  only changes by a committed diff, which the PR shows.
- **N3 (`ci.yml:60`).** The job is not a required status check: neither `pre-main` nor `main` has branch protection, and the repository
  has no rulesets (`gh api .../branches/<b>/protection` 404 for both; `.../rulesets` empty). So a red guard does not stop a merge; it is
  read by whoever merges. That is how every other check in this repository works today, so it is consistent, but the guard's whole
  purpose is a merge made by mistake, and a required check is the form that catches that without a reader. The owner's call; recorded,
  not recommended.
- **N4 (`scripts/no-debug-sources-names.sha256`).** The list is a snapshot of the one tools commit. dev has since added more debug-only
  files (for example under `app/src/debug/.../burst/` and `app/src/testDebug/.../sensor/`, `git diff --name-only 7c9cdb0d1 origin/dev`);
  the `debug/` ones are caught by check 1, the `testDebug/` ones by neither check, though a test of a debug class cannot compile without
  it, so the build would fail instead. If the tools grow outside the two folders, the list needs the new names, and the header at
  `verify-no-debug-sources.sh:12-15` says how it was made. The dispatch scoped the list to the two tool commits, and for those it is
  complete.
- **N5 (`verify-no-debug-sources.sh:50`).** "The PR's own file list shows which" is right for a `pull_request` run; on a push to
  pre-main or main there is no PR to look at, and the reader is left with `--list` locally, which the same message also gives. Wording
  only.
