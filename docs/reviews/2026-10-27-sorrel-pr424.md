**S1. The Loading state renders a fourth text, and the coder's item 5 describes it wrongly.**
`A/ui/map/layers/ReferenceLayerCard.kt:100-101`: while `copy` is `Loading` the card shows the Sources line as
"Sources: Forest Service · CC BY 4.0. BLM · public domain." with no hint, then the line rewrites itself when the
kept copy arrives. The coder's item 5 says "Nothing shows for the few milliseconds before the stored copy is
read"; the code shows a dateless line, which is a fourth state -1717 does not list. No test observes it: every
test scope is `Dispatchers.Unconfined` with non-suspending fakes (`T/ui/map/layers/ReferenceLayerCardTest.kt:72,
80-83`), so `Loading` is gone before the first frame. On a phone the first read opens the DataStore file, so the
flicker is real if short. Fix either way: render no Sources line while `Loading` (which is what item 5 claims), or
keep the line and correct the report. I recommend the first: a line that changes under the eye is the "did it
break?" moment "Don't make me think" warns about.

**S2. The one network class has no test.** `A/data/referencetrails/WorkerReferenceTrailsManifestSource.kt` (41
lines) carries the 256 KB operating limit (`:30`, `request(MAX_MANIFEST_BYTES + 1)`), the non-200 path (`:28`) and the
no-body path (`:29`), and nothing exercises any of them. The repo already uses a mock web server in tests
(`T/map/MapUserAgentTest.kt`, `T/map/TileRetryInterceptorTest.kt`), so a fixture-only test costs little. The cap's
arithmetic reads correct: a body of exactly 256 KB passes, one byte more fails with "over 262144 bytes". Unverified by
a run.

**4. Manifest parsing.** `parseReferenceTrailsManifest` (`ReferenceTrailsManifest.kt:34-47`) parses to a JSON tree,
so unknown keys are ignored (fixture carries `a_key_added_later`, `ReferenceTrailsManifestTest.kt:98`); sources are

**5. Fetch failures.** `ReferenceTrailsSources.fetchOnce` (`ReferenceTrailsSources.kt:91-106`): a failed fetch logs
and returns (`:94-95`); an unreadable body logs and returns (`:98-99`); only a parsed manifest replaces `copy` and is

(`A/data/remote/ApiClients.kt:26-27`). There is no backoff, so each opening after a failure does try once; that is one

## The coder's seven decisions

1. **Card replaces the list inside the sheet; swipe or tap outside closes the whole sheet.** Back is right and
   tested. The dispatch offered "the existing sheet and bubble surfaces" and the coder chose the sheet; -1717 says "a
   card opens" and no more. Two visible consequences the owner has not seen: the sheet shrinks from the list's
   height to the card's five lines when the (i) is tapped, and back again on Back (Material3 re-anchors to the new
   content height; whether that is a snap or an animation is device-only); and a swipe down with the card showing
   leaves the user at the map, not the list. **Bring to the owner**, one message with a sketch, together with item 2.
   Not a defect.
2. **The (i) is a 48 dp button after the switch.** Correct as a touch target (check 3). -1717 and the step 8 report
   §5 both say "the (i) beside 'Official trails'"; the coder placed it after the switch, at the row's far right, like
   a colour field's drag handle (`MapLayersSheet.kt:321`). A row that toggles with a trailing (i) is a reasonable
   pattern, but "beside the label" is the other reading and the owner answers from a phone. **Bring to the owner with
   two sketches**: `[Official trails (i)   ... ◉]` and `[Official trails   ... ◉ (i)]`.
3. **Also on the entry map's sheet.** The owner's ruling 4 made it "the same sheet"; the row is there since 8b, so a
   row with an (i) in one place and not the other would be the odd case. **Accept** (N2 for the missing test).
4. **A missing date takes the no-copy wording; a newer copy without a date replaces the older date.** A successful
   manifest is the current truth about the served data; showing last month's date for a source today's manifest does
   not carry would present a stale figure as current, which is closer to inventing than to keeping. "Never blank good
   dates" in the dispatch is about failed fetches, and those are kept. **Accept.**
5. **Nothing shows before the stored copy is read.** Not what the code does (S1). **Accept once S1 is resolved**
   either way; the owner need not see it.
6. **Licences are fixed text.** They are the owner's words in -1717; the manifest's `licence` field says "Public
   domain" with a capital, the card says "public domain" as the owner wrote it. A licence change upstream would need
   an app change, as it does for the credits today. **Accept.**
7. **A corrupt file is reset and logged without the settings-reset notice.** `SettingsResetListener.None`
   (`DataStoreReferenceTrailsDatesStore.kt:26`); the reset is still logged by `settingsDataStore`
   (`SettingsDataStore.kt:39`). The -660 ruling ("Reset it and say so once") was about files holding the user's
   choices; this file holds a cache the next fetch rewrites, and the notice would make the user think. **Accept.**
