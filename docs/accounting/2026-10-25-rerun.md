## Part 3: Ideas

**Already ruled, not repeated** (RECORD 2026-09-28-1644 and -1645): no in-chat polling; a fresh helper past about 200,000 tokens; a role name on each session's first line. Only the new figures are given here.

- Polling: 377 sleep commands in 217 turns cost 70.0M (22.1% of the day); Hazel alone 63.5M.
- Context past 200,000: 729 turns, 236.2M (74.7% of the day).
- Role line: 235 turns, 39.1M (12.4%), had no role matched.

**Idea A: shrink what every session re-reads.**
- *Pattern:* 95.0% of tokens are cache reads, the same context read again each turn. The smallest peak context of any session was 134,338 (Sorrel, 22 turns), so the starting load is at least part of every turn's re-read (inferred).
- *Change:* measure the fixed opening load per role, meaning the size of each session's first turn, and cut what every session loads but does not use on each turn. Reference detail moves to files the role reads at the step that needs it. Rules and checks stay in the starting context or are read at their own step, word for word.
- *Saving:* inferred, not computable from this sample. Each 10,000 tokens taken off the opening load saves about 13.7M across this day's 1,368 turns.
- *Risk:* a rule moved out of the starting context may not be read when it applies. Keep the rules where they are; move only reference text.

**Idea B: check whether pauses are rewriting the context.**
- *Pattern:* 15.4M cache writes (4.9%). bends-report's writes were 10.7% of its own total, double the day's share. Inferred: a long pause lets the stored context expire, so the next turn writes it again at write cost.
- *Change:* measure the gap between each session's turns from the timestamps, which this run's script does not do, and see whether long gaps come just before rewrites. If they do, a shorter wait or a background wait keeps the context warm. This sits under the ruled wait rule.
- *Saving:* ceiling 15.4M tokens (4.9%) if every write were avoided; the realistic figure is far lower. Inferred.
- *Risk:* none to results. A shorter wait adds turns, so measure before changing anything.

## Part 4: Would change the result (never recommended)

- **A cheaper reviewer model.** Sorrel's reviews cost 33.8M (10.7%). Reviews are the check, and the auditor must differ from the coder. Cost shown; not recommended.

## Part 5: Disclosures

**Confirmed vs inferred**
- Confirmed by the script and reconciled: totals by team, role, kind and model each sum to 316,183,632; the same total as the first run.
- Confirmed: 21 unparseable lines in 13 files (listed in `counting-output.txt`, lines 11 to 12). None fell in a turn that was counted.
- Inferred: what each task spent its tokens on (from branch names); that the five largest turns were waits; the cache-expiry mechanism behind Idea B.

**Could not determine**
- The Pi team and cloud sessions: not visible from the laptop.
- Whether the forecast team was idle or its logs are elsewhere: the script found no in-window turns.
- What the five largest turns were for.
- The fixed opening load per session: not in the output.
- Context size at the end of a session: the script records peak, not end size.
- Whether any session was restarted from scratch when it could have resumed: not measured.
- The true role of the 235 unassigned turns.
- Repeated file reads: the script counts only the Read tool. Reads by shell commands are not counted. The repeat count (Hazel 1 extra read of 58; Sorrel 1 of 7) is therefore a floor.

**Premises that were wrong**
- The script's line "sessions with window turns but unassigned role: 3 files, 412 turns" counts usage records before duplicate removal. The deduplicated figure is 235, as the role table shows. The raw output was left as produced; this report uses 235.
- The script's task header says "top 15"; only six tasks exist in the window.

**Decided beyond scope**
- The script is the earlier one copied without change, so the method matches the first run. The labelling error above was disclosed, not fixed.
- Two new ideas are given, not five. The rest either repeat ruled ideas or are small: prompt size tops out at 3,969 characters, and no compaction was found.
- Tasks were named by branch; no log was opened.
