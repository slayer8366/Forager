## Part 1: PR #429 (build 1.0.4120+gdf03f7b4)

**How it is measured.**
- **Screenshots.** The glyph colour share (±6) over x 100-1150, y 450-2300, with the existing `count.py`, at 1 s and 30 s after returning to the map. The runner is the previous session's `run.sh`, unchanged except for the output folder.
- **Recordings.** `screenrecord` at 720 × 1544, decoded at 20 fps (`frames.sh`). The exact-colour counter reads 0 on H.264 frames, because compression shifts the colours. So each frame is classed instead by a colour band: dark green for the glyphs (r < 100, b < 100, 90 ≤ g ≤ 140, g − r ≥ 25), light green for the forest. The band covers the same area. The band's own baseline is about 0.68%, from other dark-green map features, so a dip shows as 1.32 falling to about 0.68.
- **Time zero.** t = 0 is the first frame in which forest is drawn (forest share above 5%). In these recordings that frame came about 2.75 s after the launch command.
