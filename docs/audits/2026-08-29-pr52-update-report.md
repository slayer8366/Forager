## What this PR is

PR #52 started as a four-item field-test dispatch for an Oregon Mycological Society tester build
(GPX export, a visible return-to-vehicle readout, denser GPS sampling, off-track notifications).
Once the build reached real hardware, it grew into an extended hardware-feedback loop: the tester
found and reported a series of real bugs and rough edges — some in the original four items, several
in a new observation-tap/iNaturalist feature built mid-PR, and a run of List-tab and map-polish
requests — each investigated, fixed, tested, and pushed in turn. Every commit below reflects a real
report from the actual tester build or the project owner, not speculative polish.

## Commit-by-commit, in order

### 1. Original four-item dispatch

- **`6bce105`** — `TRACK-PULSE.md`, a read-only investigation of the track-recording subsystem
  (return-to-vehicle, sampling, process-death survival, off-track detection) the dispatch below was
  based on. No code changes.
- **`e44e455`** — the dispatch itself, four items:
  1. Wired the existing, already-tested `GpxCodec` to a Settings "Recorded Tracks" export action
     via the standard share sheet (mirrors the Crash Logs pattern).
  2. Gave return-to-vehicle a visible compass-strip readout — previously the bearing/distance/
     elevation `MapIconBar` computed reached a sighted user nowhere but `contentDescription`
     (TalkBack-only) and an icon tint. Found and fixed a real touch-interception bug along the way:
     `MapIconBar`'s `Surface`, vertically centered on the same right-edge column, silently swallowed
     taps on the new control on short screens.
  3. Defaulted the tester build's recording to `TrackRecordingMode.HIGH_ACCURACY` (a call-site
     override, not a changed library default) for a denser track to compare against Gaia.
  4. Routed `DetectOffTrackUseCase`'s signal to a dedicated notification channel plus vibration, on
     a 120s repeat-while-off-track cooldown.
  - 762 tests run, 761 passing; one pre-existing full-suite-only flake (`JournalTabTest`), documented
    and unrelated to this change.
- **`ea6917f`** — hardware screenshot caught a real regression from item 2: two unbounded
  `fillMaxSize()`/`fillMaxHeight()` calls stretched the whole compass strip to the map's full
  height, landing its centered content on top of `MapIconBar`'s own column. Fixed both call sites;
  added a new test against the strip's own container (the existing 48dp-touch-target test couldn't
  have caught this, since it measured a fixed-size child unaffected by the container's height).
- **`e4e3be6`** — hardware feedback that having both the compass strip's and `MapIconBar`'s
  identical return-to-vehicle controls visible at once read as confusing duplication. Removed
  `MapIconBar`'s row, keeping the one testers reported actually reaching for.

### 2. Observation-tap feature (new mid-PR, driven by hardware feedback)

- **`0c4f8d0`** — tapping an observation marker on the map did nothing (a gap left by the earlier
  osmdroid→MapLibre migration, already flagged in `SightingsMap.kt`'s own doc comment). Wired a full
  tap→detail flow: GeoJSON now carries each sighting's `observationId`, a new `onSightingTap`
  callback resolves a tapped dot back to its `Sighting`, and a dialog showed species/date plus a
  "View on iNaturalist" link.
- **`16b67f9`** — unrelated bug found and fixed along the way: status bar icons followed the
  *device's* dark-mode setting instead of this app's own persisted Night Mode preference
  (`enableEdgeToEdge()`'s default reads the wrong signal). Fixed by recomputing the system-bar style
  from the app's own theme state on every toggle. Flagged as not verified on hardware in its own
  commit message.
- **`7f51882`** — two more hardware reports: the modal dialog "got in the way of the UX" (replaced
  with a small non-blocking `ObservationBubble` floating over the map, dismissed by its own close
  icon or a tap elsewhere — catching and fixing two real bugs along the way, both via this
  composable's own interaction tests, not visual review); and "View on iNaturalist" always opened a
  browser, never the installed app (fixed by targeting the app's package explicitly first, falling
  back to the plain implicit intent).

### 3. Settings and navigation

- **`c3e098f`** — added a System Default option to the (previously Light/Dark-only) Night Mode
  setting, with a real DataStore migration for existing installs (a pre-tri-state boolean value is
  read and preserved, not silently overwritten).
- **`f5d21c4`** — hardware report that the back button didn't close the top quick-search panel or
  reliably dismiss the keyboard afterward. Investigated the existing back-navigation architecture
  first (kept its deliberate step-by-step design rather than replacing it), then added the missing
  `BackHandler` and the keyboard-dismiss calls this whole app was missing everywhere.

### 4. This session's continuation — hardware-feedback round 2

- **`93dd177`** — four items from one batch of hardware feedback:
  1. The iNaturalist app-open fix from `7f51882` still didn't work on real hardware. Root-caused via
     real research (not guessed): API 30+ package-visibility filtering silently blocks
     `Intent.setPackage()` resolution unless the target package is declared in this app's own
     `<queries>` manifest block — already solved for the maps-directions intent, missing for
     iNaturalist. Fixed with a `<queries><package>` declaration.
  2. Fresh installs now default to System Default theme instead of Light (existing installs
     unaffected).
  3. Compass strip text was still clipping — root-caused to the compass icon competing for width
     inside the same weighted row as the text; moved to its own fixed-size box.
  4. The observation bubble now anchors at the tapped marker's live screen position (re-projected on
     every camera-idle event) instead of a fixed top-of-map position, at 80% opacity matching the
     rest of the map's floating controls.
- **`71b40ff`** — added "View on iNaturalist" and a new "View on Map" action to List-tab species
  rows; the latter filters the map to just that species' sightings, with an on-screen banner saying
  so (never silently showing fewer pins than the map actually has).
- **`efe0772`** — real bug report: dismissing the bubble, then panning the map, brought it back with
  nothing tapped. Root-caused to `SightingsMap` latching "which sighting to keep re-projecting"
  internally at tap time and never being told about a later dismissal; fixed by threading the
  caller's own dismissed-or-not state back down as data instead. Also: "View on iNaturalist" moved
  onto the bubble's date line, and the bubble's sharp corner now points at the tapped marker's own
  5-o'clock position instead of just sitting centered above it.
- **`fe385c6`** — most recent commit. Three more items: removed "View on iNaturalist" from the List
  tab entirely per direct feedback ("the view on iNaturalist idea was a bad one") — deleted outright
  rather than left dead, keeping "View on Map" as the row's only action; "View on Map" now also
  auto-hides the Foraging Areas layer while its filtered view is up (restoring whatever the layer
  was set to on clear); and the map's filter banner is now horizontally centered instead of
  left-aligned, with the compass strip's own padding reduced further for legibility.
